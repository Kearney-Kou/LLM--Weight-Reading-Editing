# Task: make a neural network more accurate by editing its weights only, without training

You are the person carrying out this experiment. Please do all of the work yourself until you hand in the result; do not hand steps back to the user.
The contents of this folder are all the materials you need.

## Background: what the network does

- **Task**: frame-level phoneme classification of speech. The audio is read English from LibriSpeech. One frame is taken every 10 ms (25 ms window), and 28 MFCC features are extracted per frame.
- **Normalization**: within each utterance, each of the 28 dimensions has the utterance mean subtracted and is divided by the utterance standard deviation (cepstral normalization).
- **Input**: to classify frame t, take the 40 frames before and after it, 81 frames × 28 dimensions = 2268 numbers. The flattening order is "time outer, feature inner", i.e. input index i = t*28 + f. t = 0..80; t = 40 is the centre frame being classified, t < 40 is the past and t > 40 the future; f = 0..27 is the MFCC dimension. Parts of the window that extend beyond the start or end of the utterance are filled with 0 and never cross into another utterance.
- **Output**: 42 logits; the phoneme for each index is given in `tools.PHONEMES`. Only labels 0–39 actually occur; 40 ([SOS]) and 41 ([EOS]) never occur as labels. 0 is silence [SIL].
- **Network**:
  ```
  h1 = relu(x @ W1 + b1)      W1: 2268 x 1024
  h2 = relu(h1 @ W2 + b2)     W2: 1024 x 1024
  logits = h2 @ W3 + b3       W3: 1024 x 42
  ```
  No BatchNorm, no Dropout. 3,416,106 parameters in total.
- **How it was trained**: AdamW (lr 1e-3, weight decay 0.01, batch 1024), on 12,000 utterances (15,203,231 frames). Training was stopped at step 9,400 (9,625,600 frames seen, about 0.63 epochs), when accuracy first reached about 70%. In other words, it is **undertrained**.

## Materials

- `subject_net.npz`: the network to edit (W1, b1, W2, b2, W3, b3).
- `dev_A_part1.npz`, `dev_A_part2.npz`: **practice set A**, 1351 utterances, 947,349 frames, with labels.
- `tools.py`: loading data, building input windows, forward pass, evaluation, saving. See the notes at the top of the file.
- The original network's accuracy on A is 0.6980.

There is also an **exam set B**: 1352 utterances from the same distribution as A (different utterances). You cannot access it. After you hand in, the experimenter will evaluate once on B, and that is the final score.

## Goal

Edit the weights of `subject_net.npz` to make the network's accuracy on exam set B as high as possible.

## Rules

**Forbidden:**
1. Any form of training: backpropagation, autograd (`requires_grad`, `backward`), optimizers, gradients.
2. Solving for weights directly with "minimize the loss or errors on A" as the objective. This includes iterative fitting, closed-form solutions (e.g. solving for a weight matrix directly with least squares, logistic regression or LDA), and automated search (a program that repeatedly tries weights and selects by effect, e.g. random search, grid search, coordinate descent).
3. Internet access.
4. Reading anything outside this folder: do not search or view past conversations, memory or project documents, and do not request access to other folders. All information the experiment needs is in this folder; extra information would invalidate the experiment.

**Allowed:**
- Reading the weights and doing any analysis.
- Using `forward` to run any network (original or edited) on A, looking at activations, and looking at the original network's confusion matrix and errors, without limit.
- Using data statistics (means, directions, frequencies, correlations, etc.) to understand the network and to construct edits. But for every edit you must be able to say in one sentence what it fixes and why the change should help.

**Evaluation budget: 20. Each call to `evaluate` (measuring an edited network on A) uses 1, and is recorded in `eval_log.jsonl`. Apart from `evaluate`, do not use A's labels to compute an edited network's accuracy or loss. You may iterate as "hypothesis → edit → evaluate → keep or revert", but before each evaluation write down what you expect to see.**

## Hand-in

1. Save the edited network as `edited_net.npz` in this folder (with `tools.save_net`).
2. Write `修改说明.md` [edit report], containing in order:
   - Diagnosis: where you think the network goes wrong, with evidence (the numbers you computed);
   - Edits: what each one changes and why;
   - Prediction: what accuracy you expect on B, and why.
3. Append every piece of code you ran, in order, to `代码记录.md` [code log], so that the experimenter can check for rule violations.
4. If you work on a copy of this folder (e.g. copied to another machine), you must finally write `edited_net.npz`, `修改说明.md`, `代码记录.md` and `eval_log.jsonl` back into this folder itself.
